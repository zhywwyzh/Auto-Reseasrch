# 无人机 Auto Research 研究启动方案

整理日期：2026-11-05。本文保存本次对话已经形成的研究方案；不是已完成实验的结果报告。完整细节保存在交互面板源码中，参考资料见 [文献清单](references.md)。

## 1. 研究定位

区分三个目标：

1. 用 AI 改进无人机算法：主要证明导航方法的贡献。
2. 研究 Auto Research：主要证明研究过程在多个任务上更有效、更可靠或更节省预算。
3. 建设内部科研工具：主要提高生产率并积累证据与实验资产。

建议先建立共用原型，再根据小规模对照实验确定首篇论文的主贡献。

## 2. 候选课题

**条件感知的文献综合与预算受限实验选择。**

研究问题：在固定研究预算下，将文献结论的适用条件与候选方法的反证需求连接起来，能否提高无人机探索改进在未见场景和端侧约束下的复验成功率？

新颖性尚待验证。EPOCH 已涉及证据治理、主动反证和独立重跑，Co-Scientist 已涉及假设生成与筛选。贡献需要具体到条件表示、实验选择机制和受控实验收益。

## 3. 文献与综述原型

先研究未知环境中的无人机探索，后扩展到语义目标搜索和语言导航。初期收集约 30–50 篇候选论文，精选 20–30 篇全文。

记录论文身份、版本、任务、输入、传感器、地图、动力学、计算条件、基线、支持证据与限制。Related Work 用于发现文献，关键判断回到原始论文。预印本与正式版去重；不同论文重复引用同一结果不计作独立证据。

综述输出应有任务分类、方法比较、矛盾、适用边界和研究缺口。评价引用真实性、主张支持、关键主题覆盖和条件保留；文章流畅不代表证据充分。

## 4. 最小研究闭环

研究任务合同 → 文献证据库 → 假设与实验计划 → 受限代码修改 → 仿真执行 → 独立评分 → 留出场景复验 → 端侧验证 → 论文生成。

第一项任务只允许修改 frontier 排序、视点选择或失败恢复中的一个模块。固定定位、地图、局部规划器、控制器、传感器和评分器。

每个假设包含机制解释、最近邻方法、预测、竞争性解释、可推翻条件和最小判别实验。模型给出的理论解释、已有定理、待证明命题和经验观察分开记录。

示例假设：路径重复代价可能减少回访，但可能过早放弃狭窄入口。应在环形、死胡同和遮挡入口场景下检验，同时排除速度、控制器和观测次数的混杂。此示例不宣称新颖或有效。

已有项目曾记录并撤回混入控制律差异的探索 A/B 比较，可作为混杂识别案例；撤回的数字不能用于证明算法提升。

## 5. 双层评测

### 科研系统

- 固定预算内独立复验通过的改进数。
- 首次有效改进的成本、误报与漏报。
- 人工介入时间，失败与重试的总成本。
- 引用支持率、条件提取准确率、假设可实施率。

### 无人机系统

- 几何探索：固定时限覆盖、覆盖曲线、T90/T95 达成率、重复路径、碰撞与接管。
- 语义搜索/VLN：任务成功、错误目标、适用的路径效率、指令完成情况。
- 部署：端到端 p50/p95 延迟、内存、功率模式、超时与降频。

未达到 T90 的运行不得删除或伪造完成时间；覆盖分母固定，2D 面积与 3D 体积区分。模型推理频率与闭环决策频率分别测量，仿真、HIL 和实飞分别报告。

### 对照与统计

最低对照包括固定基线、适用的常规参数搜索、同工具同预算的强单 Agent、相关科研流水线和拟议方法。消融条件化证据、实验选择、反证和跨轮记忆。

按建筑或场景族划分开发、验证和最终盲测集；搜索不访问最终盲测。研究搜索重复与导航随机种子分开记录，按任务和场景簇估计不确定性。

可先做 3 个研究子任务、每任务 3 次独立搜索、4 个研究策略的 pilot。若每次搜索至多 10 个候选、每候选 5 个开发场景，则上限为 1,800 个 episode；必须先用 10–20 个 episode 标定成本并调整规模，另留独立复验预算。这是规划示例，不是正式样本量依据。

## 6. 模型、算力与部署

外层科研系统运行在工作站/服务器，内层导航系统运行在仿真或无人机。

- 4070 Ti SUPER：开发、渲染仿真、短周期实验与可行的小模型推理。
- H20/A100：批量实验、离线模型服务及必要的训练；具体卡型、显存、数量和配额待核对。
- Orin-NX：导航部署、延迟/资源测量、HIL。
- 前沿推理/编码模型：初期可通过 API 使用；用本任务的 10–20 个测试比较至少两种可用模型，记录版本、工具和预算。

初期使用明确状态机、结构化文件和数据库即可。是否采用多 Agent，应与同预算单 Agent 比较。优先验证研究机制，再决定是否训练科研专用模型。

## 7. 16 周路线

1. **第 1–2 周：定义与学习。** 阅读核心论文，建立文献卡；冻结已有探索基线，在少量场景确认重复性。交付任务合同、文献清单和可重复基线。
2. **第 3–4 周：文献助手。** 实现证据片段、条件卡和短综述；对比直接长上下文、普通 RAG 和综述流水线。
3. **第 5–6 周：最小研究闭环。** 针对一个失败提出假设、修改一个模块、运行仿真、如实报告正负结果。
4. **第 7–8 周：选题验证。** 做强基线对照与消融，检查最近工作，决定继续、收缩或转向。
5. **第 9–12 周：正式仿真。** 扩展任务和场景族，完成独立重复、成本统计、失败分析与盲测。
6. **第 13–14 周：端侧与 HIL。** 测量 Orin-NX 的端到端表现并筛选候选。
7. **第 15–16 周：实机与写作。** 比较预先选定候选与固定基线，保留接管和失败，按已核验结果生成论文。

此安排按约两名主要参与者估算。单人先完成前 8 周范围；时间不构成实验成功或论文接收保证。

## 8. 第一周交付

- 一页任务合同：目标、范围、可修改模块、指标、预算、失败和停止规则。
- 冻结代码、镜像、地图、传感器、控制参数和评价脚本。
- 在 5 个场景各跑 3 次，优先解决不可重复性。
- 精读 AutoSurvey、OpenScholar、AI Scientist-v2、AstaBench 和 EPOCH。
- 收集约 30 篇领域候选论文，先人工精读其中 10 篇。
- 针对一个常见失败写 3 个竞争性解释及 1 个最小判别实验。
- 周报分别列事实、未验证假设、失败证据、下一实验及预算。

## 9. 最终研究包

冻结文献清单、证据卡、任务合同、代码与环境、全部候选和失败、搜索轨迹、原始日志、独立评分器、统计绘图脚本、人工介入记录、部署证据和可追溯稿件。

若收益仅来自更多预算、更强模型或一张地图，不归因于新研究机制；若只会调参，与标准搜索比较；若复验失败，保留负结果并分析失效条件。
