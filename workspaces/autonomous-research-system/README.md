# 自动研究系统 ARS

ARS将任务、模型调用、原始错误、代码修复和验收保存在持久账本中，由后台调度器接续执行。系统源码与公共规则进入Git；每个实际任务的内容和运行配置仅留本地。

公共版本没有预置课题、会话映射、固定服务器或科学授权。`init_local.py`只创建空白登记和说明页面；新的实验/论文流程必须绑定当前课题忽略区中的契约与验证器，没有默认的科学验收替代品。本机旧执行端可通过忽略的 `.local/system-modules/` 保留原兼容实现，`local_extensions.py`只负责加载，不复制授权、放宽检查或导出研究内容。该目录不会出现在干净克隆中，旧科学配置及证据仍保留在各任务本地目录。

Git边界同时包含默认拒绝的文件允许清单、索引内容检查和推送历史检查。提交前运行 `python3 scripts/check_git_scope.py`；推送前运行 `python3 scripts/check_git_history.py`，共享钩子也会执行这些检查。生成的HTML/JSON、研究说明、课题适配器及课题专用测试均不上传，即使它们位于系统目录。

## 系统默认能力

模型分工由 `model_routing.py`在新调用预留时确定并冻结到请求中，适用于全部课题及固定旧执行端。创建表单或运行详情“模型分工”可配置高性能/中等性能档位，并为阶段或具体工作项覆盖模型。选择优先级：工作项指定 → 阶段指定 → 阶段对应档位 → 默认模型 → 执行器本机默认。创新探索、方案、分析、写作和评审默认使用高性能档位；实现、代码修复、验证与实验执行默认使用中等性能档位。档位不推定某模型的能力、价格或可用性，需填写执行器实际支持的模型标识。

上述阶段分工只是建议初始值。每个阶段可直接选择高性能、中等性能、默认模型或单独模型，也可恢复建议；`model_policy.phase_profiles`保存阶段的档位选择，独立于系统的工作角色分类。`phase_overrides`保留单独指定的模型，工作项覆盖仍优先。选择默认模型会跳过性能档位；选择单独模型须填写标识。恢复阶段建议清除阶段选择与阶段模型覆盖，保留具体工作项的独立配置。保存与刷新均保留选择，实际新请求使用选定结果，历史请求不追溯修改。

配置更新记录事件，只影响之后新预留的调用，不重写已有请求、不取消在途活动、不改变科学验收及预算，也不因失败自动升级到更昂贵的模型。每次请求保存选中模型、分配依据和策略哈希，CLI使用该请求的模型参数；token账本继续按实际响应元数据中的模型核对，不能用计划模型冒充实际用量归属。旧单模型配置按原默认模型兼容。CLI初始化可通过 `--model-policy <JSON文件>`提供相同策略。

运行可单独启用 `executor_auth_mode=openai_api_then_chatgpt`。两条认证路径均使用同一 Codex CLI 和已选模型。API 路径只读取 CC Switch 中唯一的 OpenAI 官方直连 Key 预设，日常 ChatGPT 登录保留在本机，凭据不写入任务请求。无唯一合格预设时采用 ChatGPT 登录。确认 API 额度耗尽时按运行记录该凭据的状态，后续走 ChatGPT，替换 Key 后重新尝试 API。只有明确拒绝且没有实际执行的调用才会在同一操作内切换，执行过的任务由控制器核对后续处置。普通限流保留原错误处理，认证路径及回退结果记录在本次操作回执。

`platform_features.py`统一定义所有已登记任务的工程能力，不按课题编号开启：完整任务指令、执行者与调用身份、生命周期时间、按范围补充要求、逐请求模型 token 账本，以及实验阶段的数据看板。新任务创建时保存能力版本并初始化用量账本；旧任务缺少该配置也按当前系统默认提供读取及后续调用接入，不改原科学配置或历史回执。固定旧执行端通过 `runtime_entry.py` 接入当前工程模块，保持科学验证器及其版本绑定。

前端按本地课题登记表发现运行，阶段来自任务台账，模型来自请求用量元数据。新课题只需按既有规则登记并创建运行，即可使用这些能力；实验阶段的看板不依赖论文工作流开关。新能力不授予实验、设备或模型预算权限；只读任务仍只读，科学流程仍须具备相应课题的验证器。已发出的旧调用不追溯重写，新要求从下一次调用开始附入。

`tests/test_platform_features.py`使用两个非预置课题编号覆盖默认初始化、跨课题隔离、旧配置继承、通用看板、运行发现及模拟流程的持久采集，避免仅用现有课题的特例证明系统能力。

## 初始化与界面

“新建研究”默认创建独立课题：用户填写新名称、研究目标与可选的初始资料/约束，`research_registry.py`自动分配 `RS-` 编号、本地私有工作区和首个运行，不依赖预置课题。登记前验证 Git 忽略与未跟踪边界；登记表加锁并原子更新，创建请求编号支持重复提交去重及中断恢复。失败保留资料和登记状态，不删除用户内容。新课题从通用的规划与资料分析流程开始，实验资源和执行授权按本课题另行配置；不会继承既有课题的科学契约或设备授权。

“已有课题新增运行”单独提供原来的选择课题入口。创建均不自动启动模型或实验。新课题自动出现在导航、阶段详情、补充要求及任务/模型用量统计中；资料保存到对应私有工作区，初始资料文件由该课题上下文指引读取。

平台界面使用 React 19 与 Astryx Research 主题（继承 Neutral，内置思源黑体），统一提供研究总览、实验进度、成果与论文、模型用量、系统管理和参考说明，支持深浅主题与响应式侧栏。首次运行或更新前端后构建：

```sh
cd workspaces/autonomous-research-system/ui
npm ci
npm run build
npx astryx doctor --built dist
```

然后在仓库根目录启动以下服务。原有页面入口由服务加载同一前端构建，原始参考页面通过 `?legacy=1` 供说明库读取。前端源码及依赖锁属于通用系统；`node_modules`、构建目录和任务数据不上传。界面只调用现有本机接口，浏览、切换主题和刷新不会派发模型调用。

总览将正在运行、各课题最近一次运行和历史运行分别展示。最近启动时间来自控制器启动事件（旧运行回退到 RUNNING 状态事件），从未启动时明确留空；报告更新时间不参与启动排序。运行卡片与详情显示完整日期、运行编号和停止原因。旧版停止记录缺少来源时保持未知，不追溯推断为用户操作。新的明确停止请求记录来源；控制器退出信号单独留痕，保留原 operation，由监督器核对后接管，不冒充用户停止。

任务详情按阶段列出工作项及实际调用请求中的执行器、模型和调用编号，区分已停止与活跃进程；原始指令和返回结果可以逐项查看。`task_trace.py`将用户补充保存在本地事件账本，支持整个研究、指定阶段或指定工作项三种范围，重复内容返回同一保存编号。补充在符合范围的新调用中作为独立上下文提供，不经过普通记忆筛选；不改写在途请求，不启动研究或扩大授权。历史补充只读还原并去重，保留旧队列。界面以请求原文和派发事件展示携带证据，不能把已保存、已加入请求或已派发当作智能体已理解或完成。草稿按运行隔离保存在浏览器会话存储，保存失败保留输入。

```sh
python3 workspaces/autonomous-research-system/init_local.py
python3 workspaces/autonomous-research-system/serve.py --port 18767
```

初始化只创建缺失的空白本地登记文件，不覆盖现存任务、服务器或资源设置，不启动模型或实验。服务默认绑定环回地址；浏览器与服务同机时访问 `http://127.0.0.1:18767/`。不代表公网可访问。

### 工作空间地址与其他设备访问

左侧“研究工作空间 → 切换工作空间地址”默认选择本机，也可以输入其他设备的 IP、`IP:端口` 或完整 HTTP/HTTPS 地址；仅填 IP 时使用端口 18767。打开后整体切换到目标设备的工作台，接口、任务、模型配置及成果文件均由目标设备提供。切换不传递原设备的任务编号或连接凭据，不会复制研究资料或启动实验；浏览器按工作台地址保存最近使用的地址。

目标设备须部署本系统并开放网络监听：

```sh
python3 workspaces/autonomous-research-system/serve.py --host 0.0.0.0 --port 18767
```

本机浏览器依然默认直接使用。网络监听开启后，本机的地址选择面板会显示可用的网络地址和连接码；其他设备直接打开该地址，首次输入连接码后即可使用，无需 SSH 隧道。连接码仅在目标设备本机显示，保存在 Git 忽略的 `.local/workbench-access.json`（权限 0600）；认证使用 HttpOnly、SameSite Cookie，默认有效30天，重启服务保留。未认证只能加载前端和连接验证，不能读取任务、成果或操作令牌；通过验证后的操作仍检查来源和操作令牌。替换该本地文件中的连接码并重启服务可使原会话失效。

双方须在可互通的局域网或 VPN；HTTP 直连用于可信内网，公网部署需要另外配置 HTTPS。默认启动命令仍只监听本机，不会自动开启网络访问。网络地址、连接码和运行数据均不进入公共源码或 Git。

本机已安装 `autoresearch-system-docs.service` 时，网页部署应通过用户级 systemd 管理，不能杀掉托管进程后用临时后台进程代替。前端重新构建后直接刷新；Python 服务代码更新后执行 `systemctl --user restart autoresearch-system-docs.service`。服务使用 `Restart=always` 自动恢复退出，使用 `KillMode=process` 保留独立研究后台进程。若命令环境没有会话总线变量，显式设置 `XDG_RUNTIME_DIR=/run/user/$(id -u)` 与 `DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/$(id -u)/bus`。部署验收须同时检查服务为 active/enabled、页面与构建资源可读取、任务API正常；临时进程的一次HTTP成功不能作为持续可用的交付证明。

本地配置包括 `workspaces/topics.json`、系统目录下的 `research-goals.json`、`execution-targets.json` 和 `resource-allocations.json`，全部由Git忽略。任务README、实现、设计、数据、结果、授权和稿件保存到该任务自身的本地目录。

`git_boundary.py`在创建、启动/重启、直接运行和预留调用前检查本地任务及独立工作树：研究路径须被Git忽略、索引中不得有研究文件；忽略区指向公共源码的符号链接也不能绕过。约束会附入后续agent上下文。公共源码与通用工具可以提交，研究内容不得写进公共目录。初始化新克隆时，会在没有自定义钩子配置的情况下启用共享提交检查。

已有初稿可通过 `ars.py init --workflow paper --revision-spec <本课题本地JSON> ...` 显式创建修订流程，不按课题编号推定权限。契约版本为 `artifact-revision-v1`，包含课题、稿件副本目录、阶段指令、所需产物角色和本课题验收脚本。控制器冻结契约与验收器哈希，逐阶段核对真实文件及本地复验结果；模型修改验收器不能通过验收。修订不会自动获得训练或设备授权，也不改变旧只读运行。实际契约、科学内容和回执只保存于对应任务忽略区。合成测试使用非预置课题验证阶段接续、范围隔离、篡改拒绝和显式授权。

## 持久执行与代码修复

`ars.py`维护SQLite任务/operation账本，`system_supervisor.py`与`recovery_control.py`负责独立于聊天和页面的后台监督。旧控制器可交接原activity和operation；状态未知时先核对回执，避免重复提交。

代码故障触发独立的 `code_repair` 操作：读取原始错误 → 自动调用agent修改隔离候选代码 → 控制器检查实际diff及原测试 → 应用已验证补丁 → 继续原任务的原验收。没有代码改动、修改既有测试、或测试未通过均不能视为修好。修复自身失败时，把新的验收报错交回修复agent，原任务保持失败。

`runtime_entry.py`与`recovery_bridge.py`给旧固定执行端接入当前修复内核；科学验证模块及原始证据仍按原绑定核验。代码修复通过不等于科学阶段通过。

## 账本与证据

独立学术写作要求同时覆盖题目、摘要和正文：围绕研究对象、科学问题、方法及有证据的认识组织论证，工程验收、重建声明和材料齐备不能充当科学贡献。`manuscript_quality.py`检查正文审计叙述及声明/内部执行报告式题目；静态检查不能替代全文科学审读。实际贡献不足不能通过改名、删局限或删负结果掩盖。写作要求附入通用任务上下文，固定旧执行端接入当前写作检查。

预备草稿可在每个运行本地的 `artifacts/drafts.json`单独登记（版本 `preliminary-drafts-v1`，含运行身份及每个文件的相对路径、标签、SHA256）；`draft_delivery.py`按身份和哈希提供读取，拒绝越界与符号链接。前端“阶段草稿与写作修订”与已核验论文交付分开，登记草稿不会改变研究阶段或复用旧评分。

“模型 Token 账目”提供所有已登记研究运行（含历史）的模型汇总及单运行筛选，显示输入、缓存输入、输出、推理输出和已观测总量，支持逐请求分页与完整 JSON 导出。跨运行按请求编号去重；只有汇总回执时保留未归属实际模型的用量，不用配置模型代替实际模型。缺失和未落盘用量作为未知，标明总数是已观测下界。统计只读，每15秒更新，不纳入未绑定的聊天与系统策略优化调用。

“任务与模型用量”默认展开各课题累计、各次研究运行及各工作项消耗，不把任务消耗藏在折叠项里。工作项可搜索、分页，并保留模型分项及缺失调用数；总览卡片、历史运行列表、实验详情和阶段表直接显示对应运行或工作项的用量。详情中的入口定位到该次运行，侧栏用量入口打开全部研究。所有显示均读取通用 token 账本，不按课题编号实现。

实验进度看板是新派发的工程验收、先导和正式实验操作的必需交付。控制器在派发上下文中提供 `experiment_dashboard`，执行智能体应先按本轮协议设计具体工作项（名称、单位、分母及依据），再启动实验；操作台直接渲染这些工作项，无需用户另行要求或启动前端服务。未知分母保留未知，研究内容和看板数据均留在本地任务运行目录。

执行智能体通过 `experiment_monitor.py plan/update` 登记设计与持续说明，主动报告当前动作、下一步、阻碍和各工作项状态。计数需绑定本次运行内的证据文件及哈希；工作项的执行者报告不替代独立科学验收。`experiment_jobs.py` 每5秒更新作业回执、日志字节数和观测时间，操作台每2秒读取；真实训练/仿真计数由训练器或只读采集器接入。说明过期、作业状态未知和未接入计数会明确显示，不用墙钟时间猜百分比。

已在运行的旧操作继续原任务，不追溯新增验收要求；界面可只读显示已有作业回执。后续新操作由控制器要求先登记设计，作业启动器检查设计，阶段验收检查各项说明。监控写入失败不得触发实验重投。

`execution_visibility.py` 是所有后续调用默认携带的状态与日志契约，包括旧配置、修复调用和固定执行端的工程覆盖层。智能体按本次任务设计 `observation`：观测来源与频率、自定义指标名称/单位/分母、运行/结束/失败/未知的判定说明，以及系统核对清单和处理动作。平台复用已有前端渲染这些数据；无需为新课题修改公共代码或单独开服务。长作业可逐行输出 `ARS_PROGRESS` 单行JSON（`at` 为UTC秒、`simulated=false`、`counters` 为实测非负整数）；指标文案与单位来自本轮设计，不按任务编号硬编码。判定说明属于执行者设计，不会自动放行科学验收。

新实验的启动与阶段检查要求完整观测设计；新作业启动前须有两分钟内更新的具体工作状态。未知、阻塞和失败工作项须列出 `checks`（具体缺项、证据、系统动作、用户动作及 `user_required`），不能只写“待核对”。契约与原调用请求绑定，删除或降级要求文件不能绕过检查。旧在途协议保留；后续调用自动采用新契约。通用本地作业按本课题登记和运行路径隔离，先验证Git边界与执行授权；只读调用不会因具备看板而获得实验权限，新课题不继承既有课题的远端授权。

`verification_monitor.py` 将核验作为工作台的一类执行记录。执行总览显示当前核验，“核验与验收”页列出对象/版本、范围、原通过依据、逐项状态、实测计数、证据、原始失败和下一步，并可查看自动刷新的日志。控制器在调用原结构/来源检查、阶段验证器和修复复验前后自动记录，长验证器每5秒保留采集心跳；心跳不增加已检查项。固定执行端通过工程覆盖层接入，原科学模块及门槛保持原绑定。

每次后续调用的 `verification_tracking` 上下文提供 `plan/update` 命令及JSON示例；智能体按任务协议设计清单并持续更新，修复后创建新记录保留旧失败。检查器也可输出 `ARS_CHECK=<单行JSON>`，字段包括 `id/label/status/criterion/detail/evidence`，可选实测 `completed/total/unit`，状态为 `pending/running/passed/failed/unknown/skipped`。已有 acceptance/compile 作业直接展示命令回执及结构化单项输出；退出码0不会覆盖失败或未封口的单项。执行者报告、命令回执和控制器验收分别标注。旧阶段说明只读兼容，缺少逐项过程时明确显示未接入，不补造结果；浏览页面不运行核验或重投作业。所有记录位于本运行忽略的 `artifacts/telemetry/verifications`。

任务、失败、修复、复验和真实成本分别留痕。`usage_ledger.py`保存逐请求模型和token元数据，缺失用量保持未知；缓存与推理token是输入/输出的子集，不重复相加。运行数据库、调用原文、用量快照、服务器回执和真实任务验收报告全部保存在本地忽略目录，不随源码上传。

工程检查、DEV与先导不替代正式实验。实现、实验、分析及稿件须绑定同版证据，失败和负结果保留，不能降低原科学门槛来制造完成。

## Git边界

公开范围是系统源码、测试、通用界面/设计说明、公共规则及必要的共享评审工具和排版模板。任务内容不因放进系统目录就取得上传许可。默认拒绝的 `.gitignore` 允许清单还排除实际任务目标、服务器地址、资源分配、token审计和运行验收快照。

```sh
python3 scripts/check_git_scope.py
git config --local core.hooksPath .githooks
```

提交钩子会检查全部索引，强制添加的本地任务文件也会被拒绝。取消跟踪只清理索引，保留本地文件；历史中的旧材料不会因此被删除。迁移前的本机任务状态说明保存在忽略的 `.local/task-context/system-task-history.md`，不作为公共系统文档上传。
